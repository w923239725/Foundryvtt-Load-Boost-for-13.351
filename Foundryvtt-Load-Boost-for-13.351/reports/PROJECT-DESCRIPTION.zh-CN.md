## 环境与计时口径

调查环境为Foundry13.351、Node20.18.0、PF1 11.11、Babele2.7.5、Ubuntu22.04、Nginx1.18。
匿名化案例世界含38世界角色、12场景、约2323聊天、57启用模组、125合集。
旧聊天实验使用更早的2322条快照，不能冒充同一基准。
浏览器使用过Chromium154侧栏和155独立窗口，视口也有变化。
新增计数会扰动性能；只有同一对照组内才做差值。

- **阶段耗时**：函数从开始到结束的时间，不代表它全是冗余。
- **包含时间**：包含子函数，不能与子函数再次相加。
- **对照收益**：在指定条件下启用/关闭/恢复的差值，不等于其他世界的保证。
- `game.ready`/`canvasReady`、首个可见帧完成、`babele.ready`是不同指标。
- 部分工作在地图出现后发生，会影响早期交互但不应算作地图出现前等待。

## 放弃、撤回或不优先推进的路线

| 路线 | 原因 |
|---|---|
| 常量公式跳过rollData getter | 有明确反例：钩子副作用、异常消失、Haunt缓存写、公式修改和访问顺序变化；约0.13s成本不是安全收益 |
| handleBonusesFor全量改Set去重 | 大列表微基准有收益，真实输入大多空、最大4项；运行改动已撤回，测试保留 |
| FormulaCacheHelper跨调用缓存/快照 | 整段仅5–6ms；注册表、getter、Roll构造副作用及错误兼容成本更高 |
| 合并max/single范围结果 | 会少一次独立求值/设置读取；随机与异常语义不等价，不能用max反推single |
| PF1 Object.create/Proxy层叠rollData草稿 | [!4547](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/merge_requests/4547)、[!4548](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/merge_requests/4548)未合并，改动11/12文件；独立探针发现枚举/JSON/数组/Set/删除问题，不适合小范围移植 |
| 删除聊天/场景，关闭ckl | 可以改变耗时，但牺牲内容或功能；只作诊断，不是本包方案 |
| 给个人迷雾加共享缓存 | 真正等待来自Babele；还会引入用户隐私/权限风险，未采用 |
| 直接替换共享Babele目录上线 | 多实例可能软链接到同一脚本目录，无法只影响目标站点；改用单域名精确URL覆盖思路，仍需现场审查 |
| Babele只加一行early return | 首版两次初始化/重复事件；已由最终single-flight候选取代 |
| 默认全开Prime Performance | 主要解决持续渲染，非本场景主要启动瓶颈；部分默认设置降低光照分辨率，不符合无损目标，未安装 |
| 泛化global设置缓存 | 可能隐藏live更新、包装错误或共享可变对象；优先讨论原生配置实验，未实施 |
